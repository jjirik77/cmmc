# Stage 2 — Learning Design Specification
## CMMC Level 2 Assessor Preparation — 5-Day Workshop

---

## 1. Content type and cognitive demand

Almost none of this material is declarative. It is **procedural** (run Phase 1; compute a score;
build a request list) and **conditional** (is this asset in scope *given* that no policy exists;
is this evidence sufficient *given* the scope; may this requirement be deferred *given* the
score and the enumerated list). Conditional knowledge is what fails under exam conditions and in
the field, because the condition is the part people drop.

That diagnosis drives three design decisions:

1. **Worked example → faded practice → independent performance**, explicitly, not implicitly.
   The evidence sequence is the clearest instance: L5 models three artifacts with the reasoning
   exposed, the tool works two with the model answer one click away, and by L8 there is no
   model answer at all.
2. **Every conditional rule is taught with its condition attached and tested with the condition
   removed.** The two conditional asset categories, the MFA partial-credit conjunction, and the
   POA&M threshold-plus-list are all taught this way, and each has a knowledge-check item where
   the naive answer is the one that drops the condition.
3. **Judgment is assessed, not recall.** No item asks which model version is current. Items
   present an artifact, an environment, or a determination and ask whether to accept it and why.

## 3. Strategy per segment, with rationale

| Segment | Strategy | Why |
|---|---|---|
| L0 | Orientation + explicit role reframing | The consultant/assessor shift is an *identity* change, not a fact. It has to be named on day one and returned to, or it does not take. |
| L1–L2 | Expository with immediate application | Foundational and genuinely declarative in part. Kept short and front-loaded so session time goes to judgment. |
| L3 | Case adjudication | Ethics taught as rules produces recitation. Ethics taught as rulings on concrete facts produces decisions. Eight scenarios, one of which the governing document does not cover — because the field is like that. |
| L4 | Rule → contested application → challenge | The categories are trivially memorable and hard to apply. Time goes to the five contested calls, not the definitions. |
| L5 | **Three-step fade**, explicitly | Watch three worked, work two supported, work the rest unsupported. This is the only place in the workshop where the fade is stated to the learner, because noticing the scaffolding being removed is itself instructive. |
| L6–L7 | Deliberate practice with immediate feedback | Objective-level determination and scoring are both high-repetition skills with unambiguous right answers. The SPRS tool gives live feedback because delayed feedback on arithmetic teaches nothing. |
| L8 | Full-task simulation, no scaffolding | Summative. Time pressure, incomplete evidence, cooperative interviewees, and social pressure are the actual task conditions. |
| L9 | Rule application + **cold transfer** | Four days on one company creates familiarity that feels like competence. The transfer test is the only instrument that distinguishes them. |

## 4. Assessment design

**Formative — knowledge checks.** 100 items, 10 per lesson. Every item is scenario- or
judgment-shaped; none asks for a version number or a date. Every distractor carries a rationale
explaining *why it is attractive*, not just that it is wrong — because the distractors are drawn
from things practitioners say confidently in the field. Answering reveals the correct option and
both rationales; the score is shown but not recorded.

**Formative — tool determinations.** 85 auto-checked selects across nine tools. Each reveals a
model answer with the reasoning exposed, including where the answer is genuinely arguable.
Free-text fields are never auto-graded — they are compared against a model answer by the learner.

**Enforced completeness.** The Evidence Triage tool refuses to treat a verdict as finished
without a *what would change it* clause, and says so. This is the single highest-signal
discriminator between Competent and Assessor-Ready work, and it is cheap to enforce mechanically.

**Summative.** The Day 5 mock assessment (workbench) and the Acuitas transfer test. Neither is
graded; both are diagnostic against the four-level competency rubric.

**Rubric.** Not Yet / Developing / Competent / Assessor-Ready, carried from the source course.
Competent is the completion standard. The rubric is published to learners in L10 and applied in
the transfer-test key.

**What is deliberately not assessed:** anything with a shelf life. There is no item on which
version of the CAP is current, what the CCP costs, or what any particular policy announcement
said — only on how to tell whether an announcement changed a requirement, which is reasoning
rather than recall. The workshop carries no dated policy layer at all.

## 5. Accessibility and UDL requirements

Specified here so they constrain the build rather than being retrofitted.

| Requirement | How it is met |
|---|---|
| Semantic structure | One `<h1>` per page; `<section>` per content block; `<table>` with `<thead>`/`<th>`; `<ol>`/`<ul>` for real lists |
| Keyboard operation | All interactive elements are `<button>`, `<select>`, `<input>`, `<textarea>`, `<a>` or `<details>` — no div-with-onclick anywhere, so tab order and Enter/Space activation come free |
| Visible focus | Inputs take a 2px amber outline with offset; default focus ring retained elsewhere |
| Labelled controls | Every field has a `<label for>`; flip cards carry `aria-label` naming the term |
| Never colour alone | Correct/incorrect carry a text label in the rationale ("Correct." / "Not this one.") and a border change, not just a fill |
| Contrast | Palette checked in both themes; body text ≥ 7:1, secondary ≥ 4.5:1 |
| Theme | Light and dark, with the choice persisted; no forced dark |
| Wide content | Every table sits in an `overflow-x:auto` wrapper; the page body never scrolls horizontally |
| Reduced motion | Only two transitions exist (card flip, hover lift), both decorative and both under 0.5s |
| Print | Every tool prints as a clean deliverable with navigation, buttons, and TOC suppressed |
| Reading order | Sidebar TOC precedes content in the DOM and collapses to the top on narrow viewports |
